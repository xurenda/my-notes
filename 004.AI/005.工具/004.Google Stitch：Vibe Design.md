**Google 三天前发了 Stitch 2.0，Figma 股价两天跌了 12%**

这不是巧合。CNBC 标题写得很直白：「Figma's stock drops 12% in two days after Google releases 'vibe design' product」。Business Insider 也跟了：「Google declares 'vibe design' is here as Figma's stock price sinks」

Figma 今年累计跌了 35%，IPO 价 33 美元，现在 25 块出头。历史最高 120 多，现在只剩零头

![[Pasted image 20260327142750.png|350]]

但让我觉得真正有意思的不是股价。是 Google 在 Stitch 2.0 里做的一个产品决策：**它不再让你从线框图开始设计，而是让你用一句话描述你想要的感觉**

Google 自己给这个东西起了个名字：**Vibe Design**

# 什么是 Vibe Design？

以前用 Figma：打开画布 → 拉组件 → 调间距 → 选配色 → 对齐像素 → 导出标注 → 交给前端

现在用 Stitch 2.0：「帮我设计一个 pngtosvg 的网站」→ 出图 → 自动生成设计系统 → 点 Play → 直接跑交互原型

**从"画"到"说"，从"手工拼"到"AI 直出"**

更狠的是这个 —— 你甚至可以直接扔一张手绘草稿进去，Stitch 帮你变成高保真界面：

![[Pasted image 20260327142857.png]]

这不只是效率提升，这是设计工作流的根本性变化

Stitch 2.0 这次更新了 5 个核心能力：

- **AI 原生无限画布**：不是传统画板，是无限展开的工作空间，草图、文字、图片、代码都可以往里扔
- **Design Agent**：设计智能体，能追踪你整个项目的演变过程，同时探索多个方向
- **Voice Canvas**：直接对着画布说话 ——「给我三种不同的菜单布局」「换个暗色系看看」——它实时改
- **Instant Prototypes**：点 Play 就能跑交互，自动生成下一屏的逻辑跳转
- **DESIGN.md**：用 Markdown 定义设计系统，可以导入导出到其他工具

而且**完全免费**

# 为什么 Figma 会跌？

先说一个事实：Figma 去年 7 月 IPO，上市首日冲到 120 多美元，现在 25.26。历史跌幅 79.30%

Google 发 Stitch 2.0 那天，Figma 单日又跌了 8.8%。两天累计跌了 12%

但你不能简单说"Google 发了个工具，Figma 就完了"。真正在发生的是更大的事情：

**AI 正在从"帮你写代码"推进到"帮你做设计"**

以前 vibe coding 让程序员慌了一阵。现在 vibe design 轮到设计师了

逻辑是一样的：

- vibe coding：你描述需求 → AI 写代码 → 你审阅修改
- vibe design：你描述感觉 → AI 出设计 → 你审阅修改

**生产者从"制作者"变成了"审阅者"**

这个转变，先发生在代码领域（Cursor、Claude Code、Codex），现在开始发生在设计领域（Stitch、Lovart、v 0）

**AI 模型的迭代速度，现在首当其冲的两个职业就是程序员和设计师**

# Stitch 2.0 真正的杀招是什么？

不是 AI 生成 UI，这个很多工具都能做

**是"从设计到代码"的完整闭环**

你看这组 Stitch 生成的 App 界面 —— 记账应用，从首页到 AI 识别小票再到确认页面，三屏一次出完：

![[Pasted image 20260327143034.png]]

这不是一张"好看的图"。这是可以点 Play 跑起来的交互原型

Stitch 2.0 支持：

- 导出到 Figma（带 Auto Layout 和可编辑图层）
- 导出到 AI Studio 和 Antigravity
- 通过 MCP Server 接入 Claude Code、Codex 等编程工具
- Skills 和 SDK 做二次开发（GitHub 上已有 2.4k stars）

这意味着：设计稿不再是一张"图"，而是可以直接流入开发流程的结构化资产

以前：设计师画 Figma → 标注 → 前端看标注 → 手动还原 → 来回改

现在：Stitch 生成设计 → 导出代码 → MCP 接入 Claude Code → 直接开始写业务逻辑

**中间那些"人肉翻译"的步骤，正在被 AI 吃掉**

# Figma 真的危险吗？

说一个可能有争议的判断：**Figma 短期不会死，但它的护城河正在变薄**

Figma 最强的不是画图能力，是协作网络 —— 全世界设计师都用 Figma，你的同事用、你的甲方用、你的开发用。这个网络效应不是一个 AI 工具能打掉的

但 Stitch 在做的事情是：**把"需要专业设计师才能做的事"，降维到"任何人都能做"**

产品经理自己出高保真原型，创始人自己做 landing page，开发者自己搞 UI —— 这些人以前都需要打开 Figma 找设计师，现在他们可能不需要了

这不是替代 Figma，而是**绕过 Figma**

就像 vibe coding 不是替代 VS Code，而是让很多人不再需要打开 VS Code

> 📍 设计工具的竞争逻辑正在变化：以前比的是"谁的画布更好用"；现在开始比"谁能让用户不用画"

# 对程序员和独立开发者意味着什么

如果你是程序员或独立开发者，Stitch 2.0 对你的实际意义可能比对设计师更大：

**第一，你的 side project 不用再等设计稿了**

以前做个产品，UI 是最大的瓶颈之一。要么自己瞎画，要么花钱找设计师，要么用模板凑。现在一句话就能出高保真界面，还能直接导出代码

**第二，Stitch 的 MCP Server 可以直接接你的编程工具**

如果你在用 Claude Code 或 Codex，Stitch 的设计资产可以通过 MCP 协议直接流进你的开发流程。设计和编码之间的壁垒正在消失

**第三，DESIGN.md 这个思路值得关注**

用 Markdown 定义设计系统，这和 `AGENTS.md`、`SOUL.md` 的思路一模一样 —— **用文本文件定义规则，让 AI 理解并执行**。设计系统不再是 Figma 里的一套组件库，而是一个 AI 能读懂的协议文件

# 最后说一个感受

2026 年 AI 的扩张路径越来越清晰了：先吃代码 → 再吃设计 → 然后是内容 → 最后是决策

每吃掉一层，就有一批人从"制作者"变成"审阅者"

**你可以恐惧这件事，也可以利用这件事。区别是：你是被替代的那个，还是拿着 AI 替代别人的那个**
