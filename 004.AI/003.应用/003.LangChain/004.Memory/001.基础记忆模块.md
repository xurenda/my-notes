# 为什么需要 Memory

大多数的大模型应用程序都会有一个会话接口，允许我们进行多轮的对话，并有一定的上下文记忆能力

![[Pasted image 20251125173909.png|500]]

但实际上，模型本身是**不会记忆**任何上下文的，只能依靠用户本身的输入去产生输出

实现记忆功能，就需要**额外的模块**去保存用户和模型对话的上下文信息。然后在下一次请求时，把所有的历史信息都输入给模型，让模型输出最终结果

Memory，是 LangChain 中用于多轮对话中保存和管理上下文信息（比如文本、图像、音频等）的组件。它让应用能够记住用户之前说了什么，从而实现对话的上下文感知能力，为构建真正智能和上下文感知的链式对话系统提供了基础

# 流程

![[Pasted image 20251125181003.png]]

1. 输入问题
2. 读取历史消息：从 Memory 中读历史消息
3. 构建提示（Prompt）：读取到的历史消息和当前问题会被合并，构建一个新的 Prompt
4. 模型处理：构建好的提示会被传递给语言模型进行处理。语言模型根据提示生成一个输出
5. 解析输出：输出解析器通过正则表达式 `regex("Answer: (.*)")` 来解析，返回一个回答给用户
6. 得到回复并写入 Memory：新生成的回答会与当前的问题一起写入 Memory，更新对话历史

> [!question] 一个链如果接入了 Memory 模块，其会与 Memory 模块交互几次呢？
> 
> 2 次，读取和写入
> 
> 1. 收到用户输入时，从记忆组件中查询相关历史信息，拼接历史信息和用户的输入到提示词中传给 LLM
> 2. 返回响应之前，自动把 LLM 返回的内容写入到记忆组件，用于下次查询

# Memory 模块的设计思路

**如何设计 Memory 模块？**

- 层次 1：保留一个聊天消息列表
- 层次 2：只返回最近交互的 k 条消息
- 层次 3：返回过去 k 条消息的简洁摘要
- 层次 4：从存储的消息中提取实体，并且仅返回有关当前运行中引用的实体的信息

**LangChain 的设计：**

针对上述情况，LangChain 构建了一些可以直接使用的 Memory 工具，用于存储聊天消息的一系列集成

![[Pasted image 20251125194422.png]]

# `ChatMessageHistory`

用于存储和管理对话消息的基础类，它直接操作消息对象（如 `HumanMessage`、`AIMessage` 等），是其它记忆组件的底层存储工具

在 API 文档中，`ChatMessageHistory` 还有一个别名类：`InMemoryChatMessageHistory`

特点：

- 纯粹是消息对象的“ 存储器 ”，与记忆策略（如缓冲、窗口、摘要等）无关
- 不涉及消息的格式化（如转成文本字符串）

```python
from langchain.memory import ChatMessageHistory

history = ChatMessageHistory()
history.add_ai_message("我是一个无所不能的小智")
history.add_user_message("你好，我叫小明，请介绍一下你自己")
print(history.messages) # 返回 List[BaseMessage] 类型
"""
[AIMessage(content=我是⼀个⽆所不能的小智', additional_kwargs={}, response_metadata= {}), HumanMessage(content=你好，我叫小明，请介绍⼀下你⾃⼰', additional_kwargs={}, response_metadata={})]
"""

llm = ChatOpenAI(model_name='gpt-4o-mini')
llm.invoke(history.messages)
"""
AIMessage(content=你好，小明！我是⼀个⼈⼯智能助⼿，旨在为你提供信息、回答问题，以及 帮助你解决各种问题。你可以问我任何事情，⽆论是关于知识、学习还是⽣活中的实际问题，我都 会尽⼒帮助你！你今天想聊些什么呢？')
"""
```

# `ConversationBufferMemory`

是一个基础的对话记忆（Memory）组件，专门用于按**原始顺序**存储完整的对话历史

适用场景：对话轮次较少、依赖完整上下文的场景（如简单的聊天机器）

特点：

- 完整存储对话历史
- 简单、无裁剪、无压缩
- 支持两种返回格式（通过 `return_messages` 参数控制）
	- `return_messages=True` 返回消息对象列表 `List[BaseMessage]`
	- `return_messages=False`（默认）返回拼接的纯文本字符串

## 基础使用

```python
from langchain.memory import ConversationBufferMemory

memory = ConversationBufferMemory()

# 保存消息到内存中
memory.save_context(inputs = {"input": "你好，我是人类"}, outputs = {"output": "你好，我是AI助手"})
memory.save_context(inputs = {"input": "很开心认识你"}, outputs = {"output": "我也是"})

# 读取内存中消息（返回消息内容的纯文本）
print(memory.load_memory_variables({}))
"""
{history: Human: 你好，我是⼈类\nAI: 你好，我是AI助⼿\nHuman: 很开⼼认识你\nAI: 我也是'}
"""
```

- 不管 `inputs`、`outputs` 的 key 用什么名字，都认为 `inputs` 的 key 是 human，`outputs` 的 key 是 AI
- 打印结果 JOSN 数据的 key，默认是 `history`，可以通过 `ConversationBufferMemory` 的 `memory_key` 属性修改

```python
from langchain.memory import ConversationBufferMemory

memory = ConversationBufferMemory(return_messages=True)
memory.save_context({"input": "hi"}, {"output": "whats up"})

# 读取内存中消息（返回消息）
print(memory.load_memory_variables({}))
"""
{history: [HumanMessage(content=hi, additional_kwargs={}, response_metadata={}), AIMessage(content=whats up, additional_kwargs={}, response_metadata={})]}
"""

# 读取内存中消息（访问原始消息列表）
print(memory.chat_memory.messages)
"""
[HumanMessage(content=hi, additional_kwargs={}, response_metadata={}), AIMessage(content=whats up, additional_kwargs={}, response_metadata={})]
"""
```

## 结合 chain

```python
from langchain_openai import OpenAI
from langchain.memory import ConversationBufferMemory
from langchain.chains.llm import LLMChain
from langchain_core.prompts import PromptTemplate

llm = OpenAI(model="gpt-4o-mini", temperature=0)

# history 输入键来自记忆类，需确保 PromptTemplate 和 ConversationBufferMemory 中的键匹配
template = """你可以与人类对话。
当前对话: {history}
人类问题: {question}
回复:
"""
prompt = PromptTemplate.from_template(template)
memory = ConversationBufferMemory(
    # memory_key="chat_history" # 可以修改 memory 数据的变量名
)
chain = LLMChain(llm=llm, prompt=prompt, memory=memory)

res1 = chain.invoke({"question": "我的名字叫Tom"})
print(res1)
"""
{question: '我的名字叫Tom', history: '', text: '你好，Tom！很⾼兴认识你。'}
"""

res2 = chain.invoke({"question": "我的名字是什么?"})
print(res2)
"""
{question: '我的名字是什么?', history: 'Human: 我的名字叫Tom\nAI: 你好，Tom！很⾼兴认识你', text: '你的名字是Tom。你今天过得怎么样？有什么我可以帮助你的吗？'}
"""
```

> [!NOTE] 说明
> 
> 创建带 Memory 功能的 Chain，并不能使用统一的 LCEL 语法。同样地，LLMChain 也不能使用管道运算符接 OutputParser
> 
> 这些设计上的问题，个人推测也是目前 Memory 模块还是 Beta 版本的原因之一

## `return_messages`

```python
from langchain_core.messages import SystemMessage
from langchain.chains.llm import LLMChain
from langchain.memory import ConversationBufferMemory
from langchain_core.prompts import
MessagesPlaceholder,ChatPromptTemplate,HumanMessagePromptTemplate
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model_name='gpt-4o-mini')
prompt = ChatPromptTemplate.from_messages([
	("system","你是一个与人类对话的机器人。"),
	MessagesPlaceholder(variable_name='history'),
	("human","问题：{question}")
])
memory = ConversationBufferMemory(return_messages=True)
llm_chain = LLMChain(prompt=prompt, llm=llm, memory=memory)

res1 = llm_chain.invoke({"question": "中国首都在哪里？"})
print(res1)
"""
{question: '中国⾸都在哪⾥？', history: [HumanMessage(content=中国⾸都在哪⾥？'), AIMessage(content=中国的⾸都是北京市。')], text: '中国的⾸都是北京市。'}
"""

res2 = llm_chain.invoke({"question": "我刚刚问了什么"})
print(res2)
"""
{question: '我刚刚问了什么', history: [HumanMessage(content=中国⾸都在哪⾥？'), AIMessage(content=中国的⾸都是北京市。'), HumanMessage(content=我刚刚问了什么'), AIMessage(content=你刚刚问了中国的⾸都在哪⾥。'], text: '你刚刚问了中国的⾸都在哪⾥。'}
"""
```

> [!tip] 注意
> 
> 我们观察到的现象不是 BUG，而是 LangChain 为保障对话一致性所做的刻意设计
> 
> 1. 用户提问后，系统应立即"记住"该问题
> 2. AI 回答后，该响应应即刻加入对话上下文
> 3. 返回给客户端的结果应反映最新状态

二者对比：

|        | return_messages=False | return_messages=True |
| ------ | --------------------- | -------------------- |
| 历史存储时机 | 仅执行后存储                | 执行前存储用户输入 + 执行后存储输出  |
| 首次调用显示 | 仅显示问题（历史仍为空字符串）       | 显示完整问答对              |
| 内部消息类型 | 拼接字符串                 | `List[BaseMessage]`  |

# `ConversationChain`

`ConversationChain` 实际上是就是对 `ConversationBufferMemory` 和 `LLMChain` 进行了封装，并且提供一个默认格式的提示词模版（也可以不用），从而简化了初始化 `ConversationBufferMemory` 的步骤

```python
from langchain.chains.conversation.base import ConversationChain
from langchain_core.prompts.prompt import PromptTemplate
from langchain.chains import LLMChain

llm = ChatOpenAI(model="gpt-4o-mini")
template = """以下是人类与AI之间的友好对话描述。AI表现得很健谈，并提供了大量来自其上下文的
具体细节。如果AI不知道问题的答案，它会真诚地表示不知道。
当前对话：
{history}
Human: {input}
AI:"""
prompt = PromptTemplate.from_template(template)

# memory = ConversationBufferMemory()
# conversation = LLMChain(
#     llm=llm,
#     prompt = prompt,
#     memory=memory,
#     verbose=True,
# )
chain = ConversationChain(llm = llm, prompt=prompt, verbose=True)

# 使用内置默认格式的提示词模版（内部包含 input、history 变量）
# chain = ConversationChain(llm=llm)

# 注意，chain 中的 key 必须是 input，否则会报错
chain.invoke({"input":"你好，你的名字叫小智"})
"""
{input: '你好，你的名字叫小智', history: '', response: '你好！是的，我叫小智。很⾼兴和你聊聊！你想讨论些什么呢？'}
"""

chain.invoke({"input":"你好，你叫什么名字？"})
"""
{input: '你好，你叫什么名字？', history: Human: 你好，你的名字叫小智\nAI: 你好！是的，我叫小智。很⾼兴和你聊聊！你想讨论些什么呢？', response: '你好！我叫小智。很⾼兴⻅到你！有什么想聊的话题吗？'}
"""
```

# `ConversationBufferWindowMemory`

`ConversationBufferMemory` 记忆类能无限的将历史对话信息填充到 History 中，从而给大模型提供上下文的背景。但这会导致内存量十分大，并且消耗的 token 非常多，此外，每个大模型都存在最大输入的 Token 限制

往往久远的对话数据不能对当前轮次的问答提供有效的信息，`ConversationBufferWindowMemory` 模块只会保存一段时间内对话交互的列表，仅使用最近 K 个交互，这样就使缓存区不会变得太大

特点：

- 适合长对话场景
- 支持两种返回格式（通过 `return_messages` 参数控制）

```python
from langchain.memory import ConversationBufferWindowMemory

# 设定窗口阈值
memory = ConversationBufferWindowMemory(k=2)

# 保存消息
memory.save_context({"input": "你好"}, {"output": "怎么了"})
memory.save_context({"input": "你是谁"}, {"output": "我是AI助手"})
memory.save_context({"input": "你的生日是哪天？"}, {"output": "我不清楚"})

# 读取内存中消息（返回消息内容的纯文本）
print(memory.load_memory_variables({}))
"""
{history: Human: 你是谁\nAI: 我是AI助⼿\nHuman: 你的⽣⽇是哪天？\nAI: 我不清楚'}
"""
```
